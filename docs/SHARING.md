# 공유 · 즉시 복사 후 카카오톡 열기 선택 (2026-10-30)

CTO 결정: 시스템 공유창 대신 공유 버튼을 누르는 즉시 복사하고, 완료 안내와 카카오톡을 열지 묻는 선택을 보여준다.

1. 정산방의 상단 `링크 공유`, 하단 링크 공유·재공유, 정산 후 입금 요청 모두 기존 안내 문구와 링크를 복사한다. 입금 요청은 기존 금액·계좌 안내도 함께 유지한다.
2. 클립보드 쓰기가 성공하면 `복사되었습니다`와 `카카오톡 앱을 열까요?`를 표시한다. 복사 실패 시 실패 안내만 보여주고 열기를 묻지 않는다.
3. `카카오톡 열기`를 선택한 경우에만 앱을 연다. 사용자가 대화방을 선택하고 붙여넣어 전송한다. 카카오 로그인·계정 연결·SDK 공유·자동 발송 기능은 추가하지 않는다.
4. `나중에`, 바깥 터치·뒤로가기는 확인창만 닫는다. 카카오톡 미설치·열기 실패도 클립보드를 지우지 않으며 수동 붙여넣기 안내를 보여준다. 다른 앱이나 스토어로 자동 이동하지 않는다.
5. 데모는 운영에 존재하지 않는 가상 방 링크 대신 기존 공개 데모 안내 URL만 복사한다. 서버 API·공유 토큰·로그인 계약은 바꾸지 않는다.

Android는 카카오톡 패키지만 조회해 시작 화면을 연다. iOS는 `kakaotalk://launch` 실행의 완료 결과를 받는다. iOS 사전 설치 조회나 전체 설치 앱 조회 권한은 필요 없다. 앱 실행 성공은 메시지 전송 성공을 뜻하지 않으므로 전송 완료 문구를 표시하지 않는다.

## 검증

- 기존 공통 테스트의 초대 URL·안내 문구·입금 요청을 유지한다. 빌드·실행 결과는 PR에 기록한다.
- iOS 화면 테스트는 카카오톡이 없는 CI 시뮬레이터에서 취소·열기 실패를 각각 독립 실행한다. 각 실행 전 호스트 `simctl pbcopy`로 구분 가능한 초기값을 넣고, 화면 조작 직후 `simctl pbpaste`의 실제 값을 전체 데모 안내 문구와 비교한다. 따라서 이전 실행의 잔여 값으로 통과하지 못하며 취소·실패 후 내용 유지도 각각 검증한다. 원문은 로그에 남기지 않는다.
- 실제 카카오톡이 설치된 iPhone·Android에서 앱 실행·대화방 수동 붙여넣기는 별도 확인이 필요하다. 테스트에서는 실제 대화방에 메시지를 보내지 않는다.
- 기존 TestFlight 0.1.0(9)는 이전 시스템 공유창 방식이다. 이 변경은 새 빌드의 설치·검증 후 제출한다. PR1과 학습용 diff는 보존한다.

### iOS CI 환경 확인

최신 iOS26.5에서도 XCTest 러너의 `UIPasteboard.general.string`에서 멈췄다. 런타임 변경으로 해결되지 않았으므로 버전이 원인이라고 보고하지 않는다. 현재 검증은 `build-for-testing` 한 번 후 화면 시나리오를 따로 실행하고, 각 취소·실패 직후 호스트의 `simctl`로 실제 클립보드를 대조한다. 호스트 복사·읽기에도20초 제한을 두며 실패·시간 초과·문구 불일치를 모두 CI 실패로 처리한다. 앱 제품 코드나 개인정보 권한은 바꾸지 않는다.

기존 시뮬레이터 선택은 JSON의 첫 iPhone을 골라 Xcode26.6에서도 iOS26.4.1을 실행했다. 실제 클립보드 읽기에서 멈춘 원본 로그와 붙여넣기 메뉴 부재를 보존했다. 설치된 iOS26.5 런타임을 사용할 수 있도록 최신 iOS 버전 순으로 선택하고 선택 결과를 출력한다. [Apple 포럼의 유사 클립보드 문제](https://developer.apple.com/forums/thread/820393)와 [해당 GitHub 이미지의 설치 런타임](https://github.com/actions/runner-images/blob/macos-26-arm64/20261013.0424/images/macos/macos-26-arm64-Readme.md)을 확인한 비교 검증이며, 같은 원인이라고 확정하지 않는다. 테스트를 건너뛰지 않고 UI15분 제한·결과 내보내기2분 제한·원본 로그 보존을 유지한다.
