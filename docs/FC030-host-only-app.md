# FC-030 총무 앱과 참여자 응답 웹의 역할 분리

- 상태: 프론트만 · 2026-11-01 CTO 결정. 구현·검증 결과는 아래에 기록한다.
- 목적: 참여자에게 앱·가입·정산방 입장을 요구하지 않고, 총무의 정확한 정산과 이미지 전달에 집중한다.
- 총무: 로그인 → 차수 금액·본인 참석/음주 입력 → 웹 응답 링크 공유 → 전체 명단 검토·제외 → 예상 금액 확인 → 명시적 확정 → 전체 정산표 이미지 저장 → 직접 카카오톡 공유.
- 참여자: 링크 → 모바일웹에서 이름·차수별 불참/논알코올/알코올 응답 → 접수 확인. 금액은 총무가 전달한 이미지로 확인한다. 음료는 안주에 포함한다.

## 화면과 호환성

실제 계정의 앱 홈에는 내가 총무인 술자리와 그 완료 기록만 표시한다. 참여 중 탭과 참여자 알림은 표시하지 않는다.
예전 참여 입구·정산방·응답·송금 경로로 들어와도 참여 화면을 열지 않고 모바일웹 응답 링크를 안내한다.
총무의 이전 송금 알림은 총무 정산방으로 보낸다. 앱 설치 여부에 따라 HTTPS 응답 링크를 앱으로 가로채지 않는다.
확정 뒤 핵심 버튼은 정산표 보기·이미지 저장이다. 정산 확정과 입금 완료는 구분한다.
실제 서비스의 대화 입력과 대화 타임라인은 숨긴다. 기존 메시지·신고·차단 데이터/API는 삭제하지 않는다.
총무의 입금 확인·계정 로그아웃/탈퇴와 본인의 참석/음주 입력은 유지한다.

API·DB·계산 규칙 변경은 없다. 기존 회원/비회원 금액·송금 API는 이전 버전과의 호환을 위해 유지하되 새 참여 웹에서 사용하지 않는다.
앱 심사 체험과 개발 목데이터의 가상 역할 전환은 기존 검증 도구로 유지한다. 운영 계정 흐름과 구분하며 후속 심사 체험 개편 시 함께 정리한다.

## 검증 계획

총무 목록/알림에서 타인의 방과 완료 기록을 제외하는지, 이전 참여자 경로가 우회 진입을 만들지 않는지 검증한다.
서버 금액을 재계산하지 않고 전체 인원·받는 사람별 송금액·조정 근거가 이미지에 유지되는 기존 검증을 실행한다.
Android 컴파일/단위 테스트와 iOS CI를 확인한다. 실기기 이미지 저장·카카오톡 첨부, 운영 적용과 TestFlight 업로드는 각각 결과를 구분한다.
