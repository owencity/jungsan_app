# 영수증 입력과 간단 N빵 · 2026-11-15

## 총무가 사용하는 화면

로그인한 총무의 홈에 `간단 N빵 · 금액과 인원만 입력`을 추가한다. 차수나 초대 링크를 만들지 않고
총금액과 결제자 본인을 포함한 인원(2~50명)을 넣는다. 앱은 서버가 계산한 한 사람당 송금액,
결제자 본인 부담, 결제자가 받을 합계를 구분해서 보여주며 같은 내용으로 이미지를 저장한다.
총액은 1원~1,000만원이다. 계산 결과는 따로 저장하지 않는다.

영수증 입력은 세 곳에서 사용할 수 있다.

- 간단 N빵: 촬영 또는 최대 5장 선택 → 한 장씩 읽기 → 사진별 총액 확인 → 합계를 입력칸에 반영 → N빵 계산.
- 새 차수/기존 차수 편집: 같은 방식으로 총액·술 항목을 확인하고 현재 차수 입력에 반영한다. 기존 `저장`을 별도로 눌러야 한다.
- 술자리의 `영수증 여러 장으로 차수 입력`: 사진별로 기존 차수를 선택·변경한다. 같은 차수의 영수증을 합산하고 차수별로 저장한다.
  아직 없는 차수는 기존 `+ 차수`에서 먼저 만들거나 새 차수 편집에서 영수증을 입력한다.

기존 값이 있으면 기존 결제액, 확인한 영수증 합계, 반영 후 결제액을 표시하고 `교체` 또는 `추가`를
명시적으로 선택하게 한다. 단순 총액만 확인하는 간단 N빵에는 술 분류를 요구하지 않는다.

## 앱과 서버 연결

앱 → Spring → Python → Spring → 앱. Python 주소나 내부 인증키는 앱에 넣지 않는다.

| 동작 | 요청 |
|---|---|
| 차수용 OCR | `POST /api/v1/gatherings/{gid}/settlement-units/{sid}/receipts/extract` |
| 간단 N빵용 OCR | `POST /api/v1/receipts/extract` |
| 간단 N빵 계산 | `POST /api/v1/settlements/quick` JSON `{total,headcount}` |

모두 기존 앱 Bearer 인증을 사용한다. OCR 본문은 JPEG 바이너리이며 multipart가 아니다.
사진은 EXIF 방향을 적용하고 긴 변을 최대 3200px로 줄여 JPEG 품질 95, 최대 8MiB로 보낸다.
인식 결과는 `schemaVersion=2`, `requiresConfirmation=true`여야 한다. null인 숫자를 0이나 1로 채우지 않는다.
앱 요청 제한은 60초다. 429/503에서는 Retry-After를 안내하고 남은 사진을 대기시킨다. 무한 재시도하지 않는다.
일반 사진 실패는 해당 사진에 표시하고 다음 사진을 처리한다. 사용자는 실패한 사진만 다시 읽을 수 있다.

간단 N빵 응답은 `{total,headcount,participantAmount,payerAmount,incomingTotal}`이다. 앱이 사람별 금액을
계산하지 않는다. 예를 들어 서버가 10,000원/3명에 3,334원·3,332원·6,668원을 주면 화면과 이미지에도 그대로 쓴다.

## 금액을 반영하는 조건

사진별로 총액·술 단가·병 수(간단 N빵은 총액만)를 확인해야 한다. 값을 고치면 확인 표시가 해제된다.
술의 단가×수량 합계가 총액을 넘거나 합친 총액이 1,000만원을 넘으면 반영을 막는다. 술 항목은 합산 후에도 차수당 100개 이하여야 한다.

기존 차수 API의 술은 병 기준이다. 잔·캔·피처·팩·미상 항목을 임의로 병으로 바꾸지 않는다.
인식한 원래 단위·항목 금액은 참고로 남기고 병 기준 단가·수량은 총무가 직접 확인하도록 한다.
사진이 읽히지 않으면 가짜 결과를 보여주지 않고 재촬영 또는 직접 입력을 안내한다.

확정된 정산은 바꾸지 않는다. 일괄 저장은 각 차수에 절대 금액으로 PUT하고 저장 완료한 사진은 다시 반영하지 않는다.
저장 전 재조회에서 원래 차수 금액이 달라졌으면 멈춘다. OCR PUT에는 `expectedInputRevision`도 함께 보내 서버가 잠금을 잡고 비교하므로, 재조회 직후 다른 기기가 고친 경우에도 오래된 입력을 거절한다. 저장 응답을 받지 못한 뒤 재시도했을 때 이미 같은 금액이면
완료로 확인한다. 여러 차수는 한 트랜잭션이 아니므로 완료한 차수와 실패한 차수를 따로 표시한다.
확인 화면에서 취소하면 기존 입력은 유지된다. Android 시스템 뒤로가기도 같은 동작이다.

## 사진 수명과 중복 범위

한 화면에 최대 5장만 보유한다. 각 사진은 JPEG bytes와 긴 변 최대 480px 썸네일로 가지고,
원본 보기에서 현재 한 장만 3200px 해상도로 디코딩한다. iOS 사진 선택도 한 장씩 변환해 Kotlin으로 넘긴다.
사진과 인식 후보는 앱을 종료하거나 입력 화면을 떠나면 유지하지 않는다.
Android 촬영 파일은 전용 임시 캐시에 만들고 결과 수신/취소 후 지운다. 전체 사진 보관함 접근 권한은 요구하지 않는다.

같은 입력 화면에서 바이트가 동일한 파일을 재선택하면 제외한다. 이미 반영한 사진은 다시 저장할 수 없다.
앱 재실행 또는 다른 각도로 다시 촬영한 동일 영수증까지 식별하는 기능은 없다. 총무가 사진·기존 금액을 확인해야 한다.
앱에서 인식을 중단해도 이미 시작한 서버/Python 처리가 즉시 멈춘다는 보장은 없다.

## 검증 범위

공통 테스트는 사진 바이너리·인증·schema·오류·취소·사용자 확인·합산·한도·순차처리·부분실패·중복 파일,
간단 계산 API 및 이미지의 1원 조정 결과 보존을 검증한다. Android 테스트와 debug 빌드, release Kotlin 컴파일을 실행한다.

iOS CI에는 iPhone 및 iPad 호환 모드에서 기존 영수증 확인/취소와 간단 OCR 총액 확인→결과 이미지 저장 창 회귀를 추가했다.
`-jsScreen quick-receipt`는 **Debug 전용 가상 데이터**이며 화면에도 표시한다. 실제 OCR/서버 계산 성공으로 간주하지 않는다.
Windows에서는 iOS 빌드를 실행할 수 없으므로 macOS CI 결과를 따로 확인해야 한다.
실제 카메라 화질·권한 거부·사진 여러 장 선택·운영 OCR 시간은 기기와 운영 연결로 확인할 대상이다.
