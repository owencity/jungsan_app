# 앱 영수증 입력 · 2026-11-04

## 범위와 연결 계약

기존 `JsColor`·`RetroSurface`·버튼을 재사용해 총무의 OPEN 차수 입력에서 사진 촬영/선택,
원본 확인, 인식 대기, 후보 수정, 명시적 반영을 제공한다. 사진과 후보는 화면 메모리에만 둔다.
Android 촬영에 필요한 임시 파일은 앱 전용 캐시에 만들고 결과 수신/취소 뒤 지운다.
사진 권한 전체 조회나 새 라이브러리는 추가하지 않는다.

앱 → Spring → Python → Spring → 앱. Spring 선행 PR #38의 커밋 d3a91a2 계약을 따른다.
다른 세션에서 작업 중인 Python 및 Spring 작업 트리는 수정하지 않는다.

- `POST /api/v1/gatherings/{gid}/settlement-units/{sid}/receipts/extract`
- 기존 앱 Bearer, JPEG 바이너리 본문, multipart/파일 경로/내부 키 전송 없음.
- 사진 정규화: EXIF 방향 적용, 긴 변 최대 3200px, JPEG 품질 95, 최대 8MiB.
  압축으로 한도를 억지로 맞추지 않고 초과하면 재촬영/직접 입력을 안내한다.
- schemaVersion=2, requiresConfirmation=true. total·unitPrice·quantity·lineAmount의 null을 유지한다.
- 429/503 Retry-After는 안내만 한다. 자동 재업로드하지 않는다. 앱 취소는 Python 추론 중단 보장이 아니다.
- 서버 호출은 최대 60초. Python 설치·ARM 실측·Spring 운영 활성화는 별도 작업이다.
  현재 운영 404/503을 인식 성공이나 가짜 후보로 바꾸지 않는다.

## 입력과 반영

총액 및 술 이름·단가·수량을 고친다. 원본의 항목 금액과 경고는 확인 자료로 표시한다.
수량 1, 누락 단가, 가격으로 역산한 수량을 만들지 않는다. 술의 단가×수량 합계가 총액을
넘으면 반영을 막는다. 나머지는 안주로 표시하며 음료는 기존처럼 포함한다.

기존 차수 API는 병 기준 DrinkItem(name, unitPrice, quantity)이다. 잔/캔/피처/팩/미상은
병으로 자동 변환하지 않는다. 원래 인식값을 별도로 보여주고 입력 단가·병 수는 빈칸으로
두며 총무가 기존 병 기준으로 직접 확인하거나 해당 항목을 빼고 직접 입력하도록 한다.
이는 용기 단위 확장 전의 제약이다. 주종·용량·confidence로 병 수를 추측하지 않는다.

확인 버튼은 기존 차수 입력의 총액/술 목록만 교체한다. 결제자·본인 응답·인원은 유지한다.
OCR로 저장/정산 확정 API를 호출하지 않는다. 취소/실패/뒤로가기는 기존 입력을 보존한다.
Android 시스템 뒤로가기도 영수증 입력만 닫고 기존 차수 편집 화면으로 돌아온다.
재촬영 후보는 이전 후보와 더하지 않고 명시적 반영 시 전체를 교체한다.

## 검증

공통 테스트에서 바이너리 요청·인증·오류/취소·null 보존·병 이외 단위·명시 확인·입력 한도를 검증한다.
Android 빌드/테스트와 iOS CI 컴파일을 별도로 기록한다. 실제 촬영 선명도·권한 거부·카카오
로그인 세션의 운영 OCR 연동과 ARM 지연은 실기기/서버 활성화 후 확인한다.
